# 시놉시스 (Synopsis) — 장르 확정

## 장르 · 핵심 루프

**대규모 디펜스 (mass-object defense).** 화면 밖에서 오브젝트(적)가 **대량으로, 파도처럼** 몰려오고,
플레이어는 그것들이 목표 지점에 도달하는 것을 **막는다**. 도달을 허용하면 실점/패배.

- 핵심 루프: 웨이브 스폰 → 적 다수가 경로/영역을 따라 진격 → 플레이어가 배치·조작으로 저지(사격·설치·직접) → 자원 획득 → 다음 웨이브 강화. 목표 지점 HP 0 = 패배, 전 웨이브 생존 = 승리(또는 endless 점수).
- "대규모" 가 설계 제약의 중심: **동시 수백~수천 오브젝트**를 스폰·이동·충돌·렌더·파괴한다.

## 확정값

| 항목 | 값 |
|---|---|
| 장르 | 대규모 디펜스 (tower/horde-defense 계열) |
| 시점 | (미정 — 탑다운/쿼터뷰가 대규모 가시성에 유리, 3D 셀 셰이딩 유지 가능) |
| 주인공 | (미정 — Unity-chan 을 플레이어 유닛으로 쓸 수도, 논플레이어 방어 구조물 중심일 수도) |
| 톤 | 카툰/셀 셰이딩(`docs/toon-rendering.md`) |
| 승패 | 목표 지점 방어 성공/실패 + (선택) endless 점수 |

## 이 결정이 바꾸는 것 (엔진 우선순위)

"대규모 오브젝트" 가 `docs/roadmap.md` 를 재정렬한다 — 캐릭터 연출보다 **다수 처리**가 먼저:

- **엔티티/스토리지**: 수천 개 동질 오브젝트 → `entity-lifecycle-design.md` §3A(연속 struct 배열) + SoA. 개별 `new` 금지, `reserve`.
- **오브젝트 풀링**: 적·투사체·이펙트는 `core::ObjectPool<T>`(`scrollable-list-and-pool.md` §1.1 — 아직 미구현) 로 재사용.
- **브로드페이즈**: 균일 그리드 — 다수 대 다수 충돌·타겟 범위 질의에 필수(선형 스캔 N² 불가).
- **레이캐스트 / 범위 질의**: 타워가 사거리 안 적을 고름 → `roadmap.md` §2.2 (`RaycastClosest` / 범위 overlap).
- **인스턴싱 렌더**: 같은 메시 수천 개를 draw call 소수로 (`MeshPass3D` 인스턴스 버퍼).
- **웨이브/스폰 시스템**: 데이터 주도 웨이브 테이블 → 시간에 따라 스폰.
- **데미지/HP**, **목표 지점 + 패배 판정**, **자원/경제**.
- 캐릭터 스켈레탈 애니메이션은 여전히 필요(플레이어 유닛/보스)하지만 **적 다수는 스켈레탈 대신 저비용**(빌보드 스프라이트 or 단순 메시 + 인스턴스)이 맞을 수 있음 — 시점 확정 후.

`docs/roadmap.md` §3 을 이 관점으로 갱신했다(디펜스 우선순위 반영).

## 아직 결정 필요

1. **시점** — 탑다운/쿼터뷰(대규모 가시성) vs 3인칭(기존 데모 자산 재사용). 레벨·카메라·적 표현 방식을 좌우.
2. **플레이어의 저지 수단** — (a) 배치형 타워, (b) 직접 조작 유닛, (c) 혼합. `Simulation` 콘텐츠 설계의 축.
3. **적 표현** — 스켈레탈 3D / 단순 메시 인스턴스 / 2D 스프라이트. "대규모" 예산이 여기서 갈림.

## 사용 방법 (How to use)

- 위 "아직 결정 필요" 3개가 정해지면 표를 확정값으로 덮고, `roadmap.md` §3 과 `Simulation` 콘텐츠 설계를 그에 맞춰 구체화한다.
- `game-settings.md`·`scene-flow-design.md` 는 이 문서와 독립적으로 이미 동작한다.
